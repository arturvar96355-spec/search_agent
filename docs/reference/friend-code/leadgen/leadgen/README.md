# leadgen — генератор B2B-лидов из 2ГИС + поиск агентств-партнёров

> **Два режима:**
> **клиентский** (по умолчанию) — ищет организации-клиентов с жалобами на связь в отзывах 2ГИС;
> **partners** (`parser partners`) — ищет агентства-партнёров через каталоги и собирает их email с сайтов.
> Ниже сначала описан клиентский режим, режим partners — в разделе 10.

**Передаточный документ. Прочитай целиком — тут всё, что делает инструмент, как он устроен и как его развивать.**
Если ты Claude/ассистент нового разработчика — это твой единственный источник правды по проекту; ниже перечислены ВСЕ возможности, текущее состояние и планы.

> Первый раз в проекте? Начни с **`ПРОЧТИ_ПЕРВЫМ.md`** (короткая вводная и первые 15 минут),
> оперативное состояние — в **`HANDOFF.md`**.

---

## 1. Идея

Инструмент ищет организации, которым **в отзывах жалуются на связь** («не дозвониться», «не берут трубку», «не перезвонили»), и отдаёт их как **тёплые лиды** под продажу бота-автоответчика / услуги обработки звонков. Логика: если бизнесу жалуются, что до него не дозвониться — он теряет клиентов на пропущенных звонках, значит ему есть что продать.

Источник: **2ГИС** (телефоны + тексты отзывов). Обогащение: **DaData** (ИНН, руководитель). Доставка: **Telegram-бот**.

## 2. Возможности (полный список)

### Три режима работы (Telegram-бот)

| Режим | Кнопка / команда | Что делает |
|---|---|---|
| **Разовый поиск** | 🔎 «Подобрать сейчас» | Ниша → город → объём (10/20/50). Парсит сейчас, ~5 мин, стримит карточки. В конце — топ-5 по приоритету + Excel. |
| **Просмотр базы** | 📋 «Посмотреть базу» / `/base` | Мгновенно показывает уже накопленные лиды по приоритету, страницами по 5, + «Вся база в Excel». |
| **Фоновый сбор** | ▶️ «Собрать базу в фоне» | Коллектор сам крутит все ниши×города, копит горячие лиды в базу до цели (100), шлёт «➕ Лид N/100», потом стоп. Стоп вручную: `/stop`. |

### Что попадает в карточку лида
Название · проблемы из свежих отзывов · **телефон** · **ИНН + ФИО руководителя** · **💰 оценка платёжеспособности** · тип (ИП/юрлицо) · сайт · соцсети · рейтинг · кнопка «🔎 Подробнее по ИНН» (полная карточка юрлица из реестра: статус, ОГРН, адрес, ОКВЭД).

### Ключевые функции
- **15 ниш** (авто, клиники, стоматологии, красота, фитнес, юристы, ветклиники, недвижимость, ремонт техники/квартир, обучение, еда, перевозки, праздники, клининг) + **8 городов** + режимы «все ниши» / «все города».
- **Фильтр свежести отзывов** — жалобы учитываются только из отзывов 2023+ (старьё неактуально).
- **Оценка платёжеспособности** — 💰/💰💰/💰💰💰 по числу отзывов + возраст + тип + сайт (прямых финданных DaData на free нет).
- **Приоритизация** — топ и база сортируются по `платёжеспособность×3 + свежие жалобы×2 + есть ИНН`.
- **Дедупликация** — проверенные организации второй раз не выдаются (`seen_leads.json`); база дедуплит по ИНН. `/reset` сбрасывает журнал.
- **Экспорт в Excel** — вся база / результаты прогона одним файлом.
- **Мобильный прокси** — браузер ходит через RU-мобильный IP, 2ГИС не банит серверный адрес.
- **Браузерный поиск без API-ключа** — `SEARCH_SOURCE=auto`: пока ключ 2ГИС жив, ищем через API; исчерпан — автоматически через веб 2ГИС (см. `BROWSER_SEARCH.md`). Клиентский режим не умирает вместе с демо-лимитом.
- **Защита памяти** — 1 Chromium на процесс (семафор) + systemd-лимит; на общем сервере не заденет соседние сервисы.
- **Доступ только владельцу** — allowlist по chat_id.

### Команды бота
`/start` меню · `/base` база · `/stop` стоп сбора · `/niches` ниши · `/reset` сброс журнала проверенных (база лидов остаётся) · **`/clearbase` полный сброс** (и база, и журнал, сбор останавливается) · `/cancel` отмена поиска · `/help`.

### CLI (без Telegram)
`parser search --query X --city Y --max N [--browser-enrich --enrich --telegram]` · `parser bot` · `parser enrich file.csv` · `parser proxy-check` · `parser niches` · **`parser partners --niche all --max 50`** (см. раздел 10) · **`parser outreach [--send]`** — email-рассылка по партнёрам (dry-run по умолчанию; подключение почты и правила — `EMAIL_OUTREACH.md`).

## 3. Механика (конвейер одного лида)

1. **2ГИС API** (`catalog.api.2gis.com/3.0/items`) → список организаций по (рубрика, город). Базовые поля. На демо-ключе **не более 10 объектов за запрос** (page_size выше отдаёт HTTP 400 — есть автопонижение).
   **Ключ исчерпан/не задан?** При `SEARCH_SOURCE=auto` (по умолчанию) поиск сам уходит на
   **браузерный поиск в вебе 2ГИС** — без ключа и лимитов, но 40–50с на страницу выдачи (12 организаций).
   Подробно: **`BROWSER_SEARCH.md`**.
2. **Браузер (Playwright/Chromium) через мобильный прокси** → публичная карточка 2ГИС: раскрывает телефоны, читает **тексты свежих отрицательных отзывов**, добирает сайт/соцсети.
3. **Матчер жалоб** (`reviews.py`) → паттерны «не дозвониться / долго отвечают». Есть → лид горячий.
4. **DaData** (по чистому имени + город) → ИНН, руководитель, год, тип. Попадание ~72% (бренды-домены/латиница не матчатся — потолок).
5. **Оценка** (`score.py`) → платёжеспособность + приоритет.
6. **Карточка** в Telegram + запись в базу.

Упавшие по таймауту прокси карточки НЕ помечаются проверенными → перепроверяются позже (лид не теряется).

## 5. Настройка (`.env`)

Скопируй `.env.example` → `.env`, заполни.

**Строго обязателен только `TELEGRAM_BOT_TOKEN`** — без него бот не стартует. Остальное
включает отдельные возможности: `TELEGRAM_CHAT_ID` + `ALLOWED_CHAT_IDS` (доставка лидов и
доступ к боту), `PROXY_URL` (**обязателен на сервере** — 2ГИС банит датацентровые IP),
`DADATA_API_KEY`/`DADATA_SECRET` (ИНН и руководитель), `DGIS_API_KEY` (быстрый поиск через
API; без него поиск идёт браузером — медленнее, но работает). Что где взять — `HANDOFF.md`, раздел 8.

**⚙️ Темп фонового сбора (мощность добычи):**
> Сейчас стоит **бережный режим** — сбор идёт медленно и не грузит сервер (он временно на общем 2ГБ-сервере с другими ботами).
> `COLLECT_PER_QUERY=5`, `COLLECT_DELAY=25.0` — короткие пачки + длинный кулдаун (браузер между пачками закрывается, память освобождается).
>
> **Чтобы ускорить на новом (пустом) сервере — подними мощность в `.env`:**
> `COLLECT_PER_QUERY=20`, `COLLECT_DELAY=3.0` и перезапусти сервис. Тогда база наберётся в разы быстрее.

Прочее: `SEARCH_SOURCE=auto` (источник клиентского поиска: API, пока ключ жив, иначе браузер — `BROWSER_SEARCH.md`), `REVIEWS_MIN_YEAR` (свежесть отзывов), `BROWSER_TIMEOUT=60` (через прокси нужен большой), `COLLECT_TARGET` (до скольких лидов копить).

## 6. Запуск и разработка

### ⚡ Быстрый старт для нового разработчика
```bash
python3.12 -m venv .venv
.venv/bin/pip install -e '.[browser,enrich,partners,dev]'   # dev = pytest
.venv/bin/playwright install --with-deps chromium

```
`parser doctor` проверяет ключи, зависимости, прокси (все из пула), настройки расхода лимита
и делает по одному живому запросу к прокси и 2ГИС. С него начинай любую диагностику.

```bash
python3.12 -m venv .venv
.venv/bin/pip install -e '.[browser,enrich,partners,dev]'   # dev = pytest
.venv/bin/playwright install --with-deps chromium

.venv/bin/python -m pytest -q         # 138 тестов
```

## 8. Пределы (честно, чтобы не удивляться)

- **Тексты отзывов** есть только через браузер — платный API 2ГИС их НЕ даёт. Платный ключ нужен только для легальных телефонов и снятия лимитов.
- **Личный телефон владельца** не отдаёт ни один легальный источник (152-ФЗ). Максимум — ИНН + ФИО, дальше вручную.
- **Прокси обязателен** для сервера: 2ГИС банит датацентр-IP. Нужен мобильный/резидентный RU.
  `PROXY_URL` принимает **несколько прокси через запятую** — пул с ротацией: при серии сбоев
  браузер сам перезапускается на следующем канале (`providers/browser.py::ProxyPool`).
- **Демо-ключ 2ГИС: 1000 запросов Places API в месяц** и `page_size` максимум 10 (при 50 API даёт
  400 — есть автопонижение). При `MAX_RESULTS=50` один (рубрика, город) стоит до 5 запросов,
  поэтому **фоновый сбор выжигает лимит за пару дней**. Расход пишется в лог каждые 50 запросов.
  Платный тариф снимает и лимит, и ограничение page_size.
  **Исчерпание лимита — не смерть режима:** при `SEARCH_SOURCE=auto` поиск автоматически
  переходит на браузерный (без ключа, без лимитов, но 40–50с на страницу из 12 организаций) — см. `BROWSER_SEARCH.md`.
- **ИНН ~72%** — бренды-домены и латиница не матчатся в DaData.

## 10. Режим `partners` — поиск агентств-партнёров

Ищет не клиентов, а **агентства**, которые приведут своих клиентов (за комиссию или white-label).
Отличия от клиентского режима: другой источник (каталоги агентств вместо карт) и **сбор email с сайта**.

### Как запустить
```bash
parser partners --niche all --max 50                      # оба каталога, до 50 агентств
parser partners --urls "https://ruward.ru/smm/region-moscow/" --max 20
parser partners --niche all --no-enrich                   # только имена и домены, без захода на сайты
parser partners --niche all -o agentstva.xlsx             # свой файл выгрузки
```

### Конвейер
1. **Каталоги** (`providers/catalogs.py`) → название + сайт агентства.
   Поддержаны: **ratingruneta.ru** (данные в SSR-состоянии `__INITIAL_STATE__`, оттуда же место в
   рейтинге и ценовой сегмент) и **ruward.ru** (HTML, `a.companyratingname`).
2. **Дедуп по домену** (`dedup.deduplicate_agencies`) — одно агентство из разных каталогов = одна запись.
3. **Обход сайта** (`providers/site.py`) → главная, `/contacts`, `/контакты`, `/partners`, `/about`,
   `/services` и др. Собирает **email** (текст + `mailto:`), телефоны РФ, Telegram, блок услуг,
   находит страницу «Партнёрам». **Уважает `robots.txt`** (кэш на домен), паузы между запросами.
4. **Метки** (`contacts.py`): `niche_tags` (стоматология/клиники/авто/HoReCa/бьюти/недвижимость или
   «универсальное») и `red_flags` (**конкурент** / **медийный** / **PR** / **не наш сегмент**).
   Флаги — подсказка, а не приговор: помеченное агентство **остаётся** в выгрузке.
5. **XLSX** (`export.agencies_to_xlsx`) — 17 колонок (`export.AGENCY_COLUMNS`), лист `agencies`.

### Что в выгрузке
`name` · `website` · **`pitch`** · **`dev_level`** · **`best_email`** · `email_found` · `emails` (с типом) ·
`phones` · `telegram` · `city` · `niche_tags` · `red_flags` · `has_partner_page` + `partner_page_url` ·
`catalog_info` · `source` · `services_raw`

**Строки отсортированы под аутрич**: сначала целевые (нет разработки → конструкторы), внутри —
с найденным email и со страницей «Партнёрам» выше.

### 🎯 Колонка `pitch` — главное для аутрича (правило из брифа продаж)

Определяется по уровню своей разработки у агентства (`dev_level`, детект по тексту сайта):

| `dev_level` | Что на сайте | `pitch` |
|---|---|---|
| `none` | чистый SMM/таргет/PR, разработки нет | **«сайты + CRM»** — самая тёплая цель |
| `constructors` | сайты на Tilda / WordPress / Bitrix / OpenCart | **«только CRM»** |
| `full` | веб-разработка, свой отдел, backend, ИТ-поддержка | **«пропустить: своя разработка»** |
| `unknown` | сайт не прочитался / услуги неясны | «уточнить вручную» |

Плюс **крупные сетевые агентства** (Nectarin, SETTERS, Kokoc, Demis, Ingate… и топ-10 рейтинга)
помечаются `big_agency` и **не тратят обход** — по брифу наш размер 5–30 человек.

**Тип email** по локальной части: `partner` / `personal` / `sales` / `general`.
**`best_email`** — по приоритету `partner > personal > sales > general`.
Нет email → пусто и метка **«не найдено»** (ничего не выдумываем).

### Проверено на живых данных (2026-07-30)
ratingruneta 51 + ruward 14 → **60 уникальных** агентств после дедупа по домену;
сквозной прогон на 5 агентствах — **5/5 с email**, телефоны и Telegram собраны.

### Источники
**Каталоги** (`--source catalogs`, 9 срезов, все проверены живьём — robots разрешает):
SMM Москва (ratingruneta 51 + ruward 14), медицина/фарма (13 + 2), авто (60 + 39),
рестораны (39), бьюти (39), недвижимость (60). Выбор среза: `--niche smm|medicine|auto|horeca|beauty|realty|all`.

**Поисковая выдача** (`--source search`) — через **DuckDuckGo html-эндпоинт**.
Важно: `robots.txt` Google, Яндекса и Bing **прямо запрещает** парсинг выдачи (проверено),
а `html.duckduckgo.com` — разрешает, поэтому работаем только там. Запросы под наши ниши —
в `providers/search.py::SEARCH_QUERIES`. Оба источника вместе: `--source all`.

### Ограничения и планы
- **Другие каталоги** (workspace.ru, tagline.ru) — добавляются одним парсером в `CATALOG_PARSERS`,
  но нужна сверка их разметки на живой странице (по памяти селекторы не пишем).
- Пагинация ratingruneta через `?page=` **закрыта в их robots.txt** — не используем.
- Ручной эталон детализации (кто владелец, чей контакт, лучший вход) — `materials/outreach-15-agencies.md`;
  там же список того, что из ручной работы стоит автоматизировать.
