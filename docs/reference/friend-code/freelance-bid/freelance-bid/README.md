# freelance-bid

Сбор заказов с FL.ru и Profi.ru, автоотклик по регламенту продаж UniqOre и
уведомления в Telegram: новый заказ, отправленный отклик, ответ клиента.

Стек: Python 3.12, httpx, pydantic, typer, SQLite, Playwright, Claude API.

---

## Быстрый старт

```bash
cd freelance-bid
python3.12 -m venv .venv
.venv/bin/pip install -e '.[browser,llm,dev]'
.venv/bin/playwright install chromium
cp .env.example .env          # заполнить, см. ниже
.venv/bin/python -m fbid.cli login fl      # войти руками, сессия сохранится
.venv/bin/python -m fbid.cli login profi
.venv/bin/python -m fbid.cli doctor        # проверить, что всё на месте
```

Обязательные ключи в `.env`: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`,
`ANTHROPIC_API_KEY`. Без последнего отклики не генерируются вообще.

## Команды

| Команда | Что делает |
|---|---|
| `doctor` | эффективные настройки и состояние: доступы, лимиты, траты за сутки |
| `stats [--days N] [--telegram]` | воронка: просмотрено, отсеяно и почему, откликов, ответов, деньги |
| `bot` | телеграм-бот с кнопками: отчёт, статус, стоп-кран (запускать отдельным процессом) |
| `scan` | один проход сбора заказов с обеих площадок |
| `watch` | основной режим: сбор + автоотклик + досыл текстов + проверка ответов |
| `autobid` | один проход автоотклика по уже собранным заказам |
| `check-replies` | проверить, не написал ли клиент по заказам с нашими откликами |
| `bid-preview <url>` | показать сгенерированный заход, ничего не отправляя |
| `filter-check` | прогнать `filters.yaml` по базе: что пройдёт, что отсеется и почему |
| `pause` / `resume` | стоп-кран автоотклика (сбор и уведомления продолжаются) |
| `login fl\|profi` | ручной вход, сессия сохраняется в `profiles/` |
| `check-proxy` | проверить, что прокси работает и подменяет IP |
| `check-session fl\|profi` | жива ли сохранённая сессия биржи |
| `probe profi` | слепок кабинета для отладки вёрстки (только чтение) |

## Как устроено

**FL.ru** — сбор по официальной RSS-ленте `https://www.fl.ru/rss/all.xml`:
без авторизации, не ломается от редизайна. Полное ТЗ добирается обычным
HTTP-запросом со страницы заказа. Браузер нужен только чтобы отправить отклик.

**Profi.ru** — доска видна только под сессией, поэтому всё через браузер
с постоянным профилем.

**Тексты откликов** генерируются Claude по регламенту из `knowledge/`
(скопирован из `uniqore-sales-bot`). Модель возвращает JSON: вердикт по заказу,
метку, готовый заход и вилку цены. Правки в `knowledge/*.md` подхватываются
на следующем отклике, перезапуск не нужен.

## Как считаются деньги на Profi.ru

Profi берёт за отклик тем больше, чем дороже заказ. Плоский рублёвый потолок
работает наоборот задуманному: пропускает отклик за 380 ₽ на заказе за 2 000 ₽
(19% от бюджета — грабёж) и блокирует отклик за 650 ₽ на заказе за 50 000 ₽
(1,3% — копейки). Поэтому потолок считается как минимум из трёх величин:

| Величина | Где задаётся | Смысл |
|---|---|---|
| Абсолютный потолок | `PROFI_MAX_BID_PRICE` | выше не платим никогда |
| Доля от бюджета | `PROFI_MAX_BID_PCT` | основной критерий, по умолчанию 2% |
| Потолок площадки | `filters.yaml → max_bid_price` | может только ужесточить |

## Заказы без указанного бюджета

Их больше половины ленты, и просто пропускать их нельзя — тогда порог
`min_budget` не работает вообще. Поэтому по таким заказам **модель сама
оценивает стоимость работы** по тексту ТЗ, и эта оценка проходит тот же порог.
Заказ без суммы, который мы оцениваем в 8 000 ₽, отсеется так же, как заказ
с явными 8 000 ₽. Не удалось оценить — не откликаемся.

## Уведомления

В Telegram приходит только то, что имеет отношение к делу:

* новый заказ — **только если он прошёл фильтры** (иначе это мусор);
* отклик отправлен, с текстом и ссылкой;
* клиент написал по заказу — «проверьте личный кабинет»;
* тревоги: слетела сессия, не удалось отправить отклик.

Сводку за период присылает `stats --telegram`.

## Рейтинг заказа: кому отклик летит сразу

Каждый заказ получает оценку от 0 до 10 (`fbid/scoring.py`). Складывается из
четырёх частей:

| часть | вес | за что |
|---|---|---|
| деньги | 0–5 | бюджет заказчика или наша оценка работы. Главный вес: всё остальное вместе его не перебивает |
| витрина | 0–2 | заказ ровно про то, что мы показываем на uniqore.ru — сайт, CRM, бот, интеграции, автоматизация |
| свежесть | 0–2 | первые полчаса дают максимум, через шесть часов — ноль |
| доверие | 0–1 | отзывы заказчика, подтверждённый телефон, позиция в очереди |

**Набрал 7 из 10 — отклик уходит в ту же секунду.** Меньше — заказ
откладывается и получает свой шанс на вечернем доборе (с 21:00 по МСК,
`EVENING_SWEEP_HOUR`), если суточный лимит и деньги ещё остались.

Порог правится кнопкой в боте. Ориентиры при пороге 7 и минимуме 20 000 ₽:
свежий заказ на 45 000 ₽ по нашему профилю — 7.8, уходит сразу; заказ ровно на
20 000 ₽ — 6.5, ждёт вечера.

Заказ с понятной суммой оценивается ДО обращения к модели: холодный
откладывается, не потратив ни рубля на генерацию. Договорной заказ приходится
сначала оценить, поэтому его заход генерируется один раз и **кладётся в кэш** —
вечером он берётся оттуда, а не заказывается заново.

## Один заказчик — один отклик

Три отклика одному человеку читаются как рассылка. Ловим двумя способами:

* по заказчику, если площадка его раскрывает (Юду отдаёт ссылку на профиль);
* по тексту заявки, если не раскрывает (FL.ru прячет заказчика от гостей):
  почти одинаковые заголовки означают, что задание развесили несколько раз.

Окно памяти — `CLIENT_DEDUP_DAYS` (14 дней). Одинаковый заказ на двух разных
биржах дедупом не считается: это две разные возможности.

## Правила площадок

`fbid/policy.py` знает, где можно давать ссылки и контакты. На FL и Profi можно
и нужно. На Юду и Кворке контакты до сделки запрещены — за это владелец уже
получил месячную блокировку на Кворке (см. `docs/kwork-obrashchenie.md`).

Поэтому там из готового текста вырезаются ссылки, телефоны, почты и ники
мессенджеров, а **если вырезать пришлось — отклик не отправляется вообще**:
обрезанная фраза выглядит как попытка обойти правила. Модель предупреждена
писать такие отклики без контактов сразу.

## Управление из Telegram

```bash
.venv/bin/python -m fbid.cli bot
```

Два способа управления, оба работают:

* **Кнопка «Меню» слева от поля ввода.** Появляется потому, что бот при старте
  отправляет Telegram список команд (`setMyCommands`). Без этого вызова кнопки
  нет вообще, и человек не понимает, что боту можно писать.
* **Инлайн-кнопки под сообщением** — быстрый путь, когда чат уже открыт.

| команда | что делает |
|---|---|
| `/start` | главное меню |
| `/report`, `/week` | отчёт за сутки и за неделю |
| `/orders` | последние заказы: рейтинг, бюджет и что софт по ним решил |
| `/status` | режим работы, площадки, траты за сегодня |
| `/limits` | лимиты трат |
| `/pause`, `/resume` | стоп-кран |
| `/check` | проверить ответы клиентов прямо сейчас |
| `/help` | как всё устроено |

Команды принимаются только от `TELEGRAM_CHAT_ID` — бот тратит деньги и пишет
клиентам от лица владельца, чужие нажатия игнорируются. В логе при этом видно
чужой chat_id: если бот молчит на твои команды, значит в `.env` указан не тот.

### Лимиты

Экран `/limits` — по кнопке на каждый лимит, значение прямо на кнопке. Жмёшь →
присылаешь число → применилось, без перезапуска:

суточный бюджет на Profi, потолок цены отклика, доля от бюджета заказа,
суточные лимиты откликов **на Profi и на FL**, минимальный бюджет заказчика,
порог мгновенного отклика, неснижаемый остаток.

Правка хранится в базе и перебивает `.env`; кнопка «вернуть заводское значение»
откатывает обратно. У каждого лимита жёсткий потолок в коде — лишний ноль в
сообщении не откроет кран к балансу, а бот честно скажет, что урезал цифру.

Запускать отдельным процессом от `watch`: управление должно работать, даже если
основной цикл упал или перезапускается. Браузер при этом общий и захватывается
по очереди — два Chromium на одном профиле портят сессию биржи.

## Предохранители

Ни один отклик не уходит без прохождения всей цепочки:

1. снят стоп-кран (`pause`/`resume`);
2. по заказу ещё не откликались;
3. заказ прошёл `filters.yaml`;
4. не исчерпан суточный лимит откликов;
5. на Profi: цена в пределах потолка, суточный бюджет не исчерпан, баланса хватает;
6. модель дала вердикт «берём» и непустой заход;
7. снят `DRY_RUN`;
8. цена перечитана со страницы прямо перед списанием.

Отдельно: `DRY_RUN=true` — глобальный стоп. Софт всё считает, показывает
заходы в Telegram, но ничего не отправляет.

Ещё три предохранителя, которые не видно, пока они не сработают:

* **Один экземпляр цикла.** Второй запущенный `fbid watch` выходит с ошибкой:
  два процесса независимо решали бы по одним и тем же заказам и могли отправить
  два платных отклика на один заказ.
* **Один Chromium на профиль.** Основной цикл и бот делят профили бирж и
  захватывают их по очереди. Два Chromium на одном каталоге либо не стартуют,
  либо портят куки — а куки здесь это живая сессия, которую восстанавливают
  руками через SMS.
* **Окончательный статус не затирается временным.** Запись «отклик отправлен»
  нельзя перезаписать словами «пропущено»: иначе заказ снова стал бы свободным
  и получил второй платный отклик.

### Постоянные и временные отказы

`rejected` — причина не изменится (фильтры, вердикт модели, цена выше потолка).
Такой заказ больше не трогается, иначе он каждый цикл уходил бы в Claude API
за новым заходом.

`skipped` — временно (стоп-кран, суточный лимит, нехватка баланса). Повтор
разрешён.

`unavailable` — биржа не даёт откликнуться: уже откликались руками, заказ
закрыт, кончился пакет откликов.

## Что известно про площадки (проверено на живых аккаунтах 05.08.2026)

**FL.ru**
* Форма отклика: `#el-descr` (текст), `#el-time_from` (срок), `#el-cost_from`
  (стоимость), `#el-submit` (отправка).
* Отклики расходуемые, продаются: `/payed/#buy-offers`. Кончился пакет —
  форма просто не отрисовывается.
* Если уже откликались, формы тоже нет. Отличить одно от другого со страницы
  нельзя, поэтому оба случая помечаются как `unavailable`.

**Profi.ru**
* Доска: `/backoffice/n.php`, карточки `[data-testid="<id>_order-snippet"]`.
  Заказ: `/backoffice/n.php?o=<id>`. Баланс: `[aria-label="Баланс"]`.
* «до N ₽» в карточке — это **бюджет заказчика, а не цена отклика**.
  Проверено: у заказа с «до 1000 ₽» отклик стоит 42 ₽.
* Цена отклика есть только на странице заказа, в двух вёрстках:
  «Цена отклика … руб.» и «Отклик • … ₽».
* Отправка двухшаговая: «Продолжить» (это `div`, не `button`) открывает форму,
  затем **обязательно** заполнить текст и «стоимость от/до», и только кнопка
  `[data-testid="payment_methods_form_pay_button"]` списывает деньги.
  Без полей стоимости кнопка молча не срабатывает.
* Лимит сообщения — **500 символов**.
* Двухфазный отклик («занять очередь сейчас, текст потом») на Profi
  **невозможен**: форма требует текст до оплаты.

**Юду** (проверено 06.08.2026)
* Обычным HTTP доску не взять: перед сайтом ServicePipe, отдаёт JS-челлендж, а
  на серверные IP — сразу 403. Через Chromium с профилем и мобильным прокси
  открывается нормально, поэтому Юду читается браузером, как Profi.
* Доска: `/tasks-all-opened-all`, карточка `li[class*="TasksList_listItem"]`,
  задание `/t<id>`. Карточка даёт заголовок, «до N ₽», «Можно выполнить
  удаленно», имя заказчика и число отзывов.
* Страница задания даёт текст ТЗ, «Создано N ч. назад» и ссылку на профиль
  заказчика `/u<id>` — по ней работает дедуп по клиенту.
* Фильтр категорий на доске **клиентский**: URL вида
  `/tasks-webdevelopment-opened-all` не существует и редиректит на общий
  список, `?text=` тоже отбрасывается. Поэтому читаем общую доску (50 заданий)
  и отбираем своими фильтрами.
* **Отправка отклика не настроена** (`can_bid = False`): форма видна только под
  аккаунтом, владелец в него ещё не входил. Площадка собирает заказы и шлёт
  уведомления, но денег не тратит и в список для откликов не попадает.
* Про деньги: типичный бюджет на Юду — 3–15 тысяч. При минимуме 20 000 ₽ живая
  проверка дала 0 подходящих заданий из 50 (два наших по профилю отсеялись
  ровно по бюджету: 3 000 ₽ и 15 000 ₽). Ждать оттуда потока крупных заказов
  не стоит.

## Прокси

Мобильный LTE, обязательно **приватный** (на общем канале до 5 человек, и IP
забанят из-за чужих действий). Формат в `.env` — строка из кабинета как есть:

```
PROXY_URL=host:port:логин:пароль
```

Ротация IP каждые 5 минут рвёт соединение с `ERR_TUNNEL_CONNECTION_FAILED`.
Код это переживает (повторные попытки), но если ротацию можно выключить —
лучше выключить.
