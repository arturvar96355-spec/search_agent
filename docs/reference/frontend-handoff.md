# Frontend & Design Handoff — playbook для Claude фронтендера

> Один самодостаточный файл. Положи его в проект (например, `docs/FRONTEND_PLAYBOOK.md`) и скажи
> Claude: «прочитай целиком перед любой задачей по интерфейсу и следуй ему». Задача — красивые,
> консистентные интерфейсы и дашборды, а не «вайбкодерский» шаблон.
>
> Принцип: **структура и правила фиксированы, тема (цвет/шрифт/скругления) — через токены**, поэтому
> дизайн можно доводить потом, не переписывая компоненты.

## 1. Стек

React + TypeScript + Tailwind + shadcn/ui + **Motion** (анимации). Точечно: Kokonut UI
(анимированные компоненты), Bklit UI (графики для дашбордов), Anime.js (только мелкие эффекты).
Motion и Anime.js не смешивать в одном компоненте.

## 2. Навыки/скиллы для Claude Code (поставить один раз)

- **UI UX Pro Max** — правила и насмотренность (стили, палитры, шрифты по типу продукта):
  `/plugin marketplace add nextlevelbuilder/ui-ux-pro-max-skill` →
  `/plugin install ui-ux-pro-max@ui-ux-pro-max-skill`
- **Impeccable** — дизайнерский вкус и ревью: `/plugin marketplace add pbakaus/impeccable`.
  Команды `/impeccable shape` (продумать UX до кода), `audit`, `critique`, `polish`, `animate`.
- **SkillUI** — снять дизайн-систему с сайта-референса в DESIGN.md: `npm i -g skillui`,
  `skillui --url https://site.com`.
- **shadcn MCP** — ставить компоненты текстом: `npx shadcn@latest mcp init --client claude`.
- **Playwright CLI** — Claude сам смотрит на результат скриншотом:
  `npm i -g @playwright/cli@latest && playwright-cli install --skills`.

## 3. Жёсткие правила (нарушение = ошибка, не вкусовщина)

Проверено на реальном продукте (SkillLink):

1. **Никаких новых цветов, радиусов и размеров шрифта в компонентах.** Всё — токенами
   (Tailwind config / CSS-переменные в `globals.css`). Не хватает значения — добавь в токены,
   а не пиши числом в одном месте. **Это и есть механизм «дизайн дорабатывается потом».**
2. **Компонент проектируется один раз и переиспользуется.** Не плоди варианты кнопки/карточки —
   сначала проверь, решает ли задачу существующий компонент.
3. **У каждого экрана четыре состояния:** загрузка (скелетон), пусто, ошибка, данные. Ни одного
   экрана без них.
4. **`null` — это «нет данных», а не ноль.** Для показателей — отдельный компонент, который сам
   отличает пусто от нуля.
5. **Текст ошибки приходит с сервера** (он уже понятный) — выводится как есть, не подменяется своим
   «что-то пошло не так».
6. **Ничто не выходит за ширину экрана.** Декоративные слои (фон, свечение, частицы) —
   `position: fixed; inset: 0; overflow: hidden; pointer-events: none`. На тач-устройствах
   (`hover: none`) эффекты за курсором стоят неподвижно. У `html/body` — `overflow-x: clip`.
7. **Клавиатура и фокус.** Любое действие достижимо с клавиатуры, фокус виден; у элемента без
   текста — `aria-label`.
8. **Демо-данные помечаются** значком (badge), если это макет/заглушка.

## 3a. Признаки «AI-сайта» — чего избегать

Что сразу выдаёт вайбкодинг и делает сайт дешёвым. Проверяй каждый экран против этого списка:

1. **Всё в карточках.** Страница = набор серых коробок, глаз не понимает, что главное. → Карточки
   только для объектов, которые можно выбрать, сравнить или открыть. **Убери ~50% контейнеров.**
2. **Одинаковые блоки и серость.** Все секции на один манер, дефолтная тема shadcn. → Настрой тему
   (tweakcn), задай иерархию, ритм, акцент.
3. **Сломанная мобилка.** На 390 px кнопки уезжают, текст режется, горизонтальный скролл. →
   Проверяй 390 / 768 / 1440; главный CTA виден и нажимается без зума.
4. **Нет состояний.** Кнопка нажата — тишина; данных нет — пустой экран; ошибка — непонятно. →
   LOADING · EMPTY · ERROR · SUCCESS у каждого действия, и понятный следующий шаг.
5. **Мёртвый интерфейс.** Ни одной анимации появления/hover/перехода. → Motion, но осмысленно,
   не ради эффекта.
6. **Стоковые тексты.** Lorem ipsum, «Наша команда профессионалов», пустой оффер. → Сначала смысл:
   что предлагаем и кому, понятно с первого экрана.
7. **Случайные значения и перегруз.** Разные отступы/радиусы на глаз, чрезмерный glassmorphism,
   градиенты везде. → Всё из токенов; прозрачность и свечения умеренно.

Правило: перед сдачей прогони экран по этому списку и по чек-листу (§8). Совпал хоть один
признак — это ещё не готово.

## 4. Дашборды (основная задача)

Что должно быть на полке и как себя вести:

- **Каркас приложения:** сайдбар + шапка + область страницы; на мобильном — нижняя таб-панель.
  Всё внутри общего layout, страницы не изобретают свой каркас.
- **Показатели (KPI/Metric):** число + подпись + дельта; сам отличает «нет данных» от нуля;
  состояние загрузки — скелетон.
- **Таблицы:** сортировка, фильтры, пагинация, состояния loading/empty/error; на узком экране —
  карточки или горизонтальный скролл только внутри таблицы, не всей страницы.
- **Графики (Bklit UI или аналог):** воронка (этапы), bar (сравнение/дефицит), ring/gauge
  (процент), area/line (динамика), radar (профиль), sankey (потоки), карта (данные по регионам).
  Каждый график — с состоянием «нет данных».
- **Оверлеи:** модалки, боковые панели, тосты — из одного набора.
- **Иерархия важнее украшений.** Сразу видно главное на экране и главное действие. Карточки —
  только для объектов, которые можно выбрать/сравнить/открыть; лишние контейнеры убрать.

## 5. Как формулировать задачу Claude

- **Один промт = один компонент или один экран.**
- **Всегда называй библиотеку и компонент:** «страница аналитики на shadcn dashboard block, воронка
  на @bklit/funnel-chart, карточки на @kokonutui/card-stack, анимация появления через Motion».
- **Прикладывай референс** (скриншот/ссылку) и описывай поведение: hover, клик, скролл, уход мыши.
- **Указывай тип продукта и стиль** (SaaS-дашборд, лендинг; тёмный premium, минимализм…) — сработает
  UI UX Pro Max.
- **Правь итерациями:** «медленнее», «плавнее», «тише», «смелее».
- **Сначала смысл:** структура, тексты, иерархия. Потом визуал.

## 6. Порядок работы над экраном

1. `/impeccable shape` — продумать UX/UI до кода.
2. Подобрать стиль (UI UX Pro Max) или снять DESIGN.md с референса (SkillUI).
3. Собрать из компонентов, все значения — токенами.
4. Прогнать 4 состояния и адаптив.
5. `/impeccable audit` + `polish`, самопроверка скриншотом (Playwright CLI).

## 8. Чек-лист приёмки экрана

**UI:** иерархия ясна, главный CTA виден; карточки только для выбираемых объектов; цвета/шрифты/
отступы — из токенов, без случайных значений; не выглядит как дефолтный shadcn (тема настроена);
иконки из одного набора, шрифтов ≤ пары.
**Mobile:** проверено на 390/768/1440 (скриншот каждой); нет горизонтального скролла страницы; текст
не режется, кнопки не уезжают; CTA нажимается без зума.
**Состояния:** loading/empty/error/success у каждого действия и загрузки; после каждого — понятный
следующий шаг; нажатие всегда даёт видимую реакцию.
**Формы:** валидация с понятными сообщениями; отправка показывает loading, потом success/error.
**Анимации:** появление/hover/скролл плавные; Motion и Anime.js не смешаны.
**Тексты:** смысл понятен с первого экрана; нет lorem ipsum.
**Техническое:** в консоли браузера нет ошибок; скриншоты приложены.
