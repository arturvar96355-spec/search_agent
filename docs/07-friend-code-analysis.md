# 07. Разбор кода друга (UniqOre): что это и что из него брать

Источник: `docs/reference/friend-code/`. Статус разбора: **первый проход**. Прочитаны README, HANDOFF,
докстринги и сигнатуры основных модулей, промпты из `knowledge/`. **Ничего не запускалось.**
Утверждения о поведении взяты из документации и докстрингов, их нужно подтверждать чтением
конкретных функций перед переиспользованием. Рабочие базы и выгрузки из репозитория удалены
(контакты третьих лиц, ~100 МБ).

## 1. Что это на самом деле
Не один бот, а **три связанные системы студии UniqOre** на Python 3.12 (~1,3 МБ кода,
1 655 тестов: orbit 786, freelance-bid 673, leadgen 196). Всё в одной воронке, управление через Telegram-бота.

| Проект | Роль | Источники и каналы |
|--------|------|--------------------|
| **leadgen** | Сбор лидов | 2ГИС (API, а без ключа браузерный поиск Playwright через мобильный прокси), отзывы с жалобами на недозвон, DaData (ИНН, руководитель), каталоги агентств; Excel/CSV/JSONL |
| **orbit** | Центр: воронка, письма, ответы | Email (SMTP/IMAP), Claude пишет письма и разбирает ответы, цепочка касаний, сводки, бэкапы, веб-приложение |
| **freelance-bid** | Отклики на биржах | FL.ru (RSS), Profi.ru, Youdo, Claude пишет отклики, фильтры, лимиты трат, диалог с заказчиком, фиксация созвона |

Стек: httpx, pydantic, typer, SQLite, anthropic, playwright, pandas/openpyxl, dnspython, loguru, systemd на VPS.

## 3. Что в коде действительно ценно
1. **Guardrails в коде, не в промпте** (`outreach.can_send`, `send`): любая отправка проходит через одну функцию,
   первая непройденная проверка останавливает письмо. Ровно наш принцип из 04.
2. **Правила рассылки**: 20 писем в день на вкладку, прогрев (первый день 3 письма), одной сети одно письмо,
   личные ящики (gmail, mail.ru, yandex, proton и т.д.) исключены, служебные адреса (postmaster, abuse) исключены,
   проверка домена по DNS до обращения к модели, «стоп» в ответе закрывает контакт навсегда.
3. **Надёжность**: «письмо ушло на сервер, ответа не дождались» (`MaybeDelivered`) не отправляется повторно,
   копия в «Отправленные», возврат застрявших писем, учёт трат, остановка при пустом счёте API.
4. **Разбор ответов**: интерес, отказ, «позже» (срок запоминается), «не тот человек». Сомнение отдаётся человеку.
5. **Цепочка касаний** (первое письмо плюс 3 вдогонку, у каждого свой повод).
6. **Защита от выдумок** в промптах: не приписывать компании то, чего нет во входных данных; не обещать «покажу кейсы»;
   одна боль, один оффер, один вопрос в конце.
7. **Эксплуатация**: готовность к запуску (`readiness.py`), расписание внутри бота, бэкапы, сводки, оповещения о поломках.
8. **Тесты** (1 655) как основа для безопасных правок.

## 4. Находка, меняющая наши решения
- **Первое сообщение у друга идёт по email, не в Telegram.** В README прямо сказано: бот не может написать в Telegram
  первым (ограничение Telegram), поэтому такие сообщения только готовятся, а отправляются вручную через «Открыть чат».
- Это совпадает с нашим анализом рисков (03) и **противоречит нашему решению** «автоотправка в Telegram/WhatsApp».
  Предлагаю: основной канал первого касания — **корпоративная почта**, Telegram/WhatsApp — только вручную по готовому
  тексту. Решение за вами (вопрос В1 в 06).

## 5. Риски и проблемы, которые нельзя унаследовать молча
1. **Сбор данных с 2ГИС** через браузер и мобильный прокси обходит блокировки площадки. Это нарушение условий сервиса
   и риск для вас и для будущих клиентов. Нужна юристу и замена на легальные источники (лицензированные API, открытые реестры).
   Дополнительно: условия API Яндекса и 2ГИС по хранению данных **[не проверено]**.
2. **Стиль «не палить рассылку»**: в `style.md` велено выдавать массовое письмо за личное и **не добавлять строку об отказе**
   («ответьте стоп»). Это подрывает юридическую позицию (см. 03, ст. 18 38-ФЗ) и честность перед получателем. Для нашего
   продукта: оставить антишаблонность и запрет выдумок, но добавить прозрачность (кто пишет, откуда контакт, как отказаться).
3. **Персональные данные**: у друга в репозиторий попадали выгрузки контактов и резервные копии баз. Нам нужны отдельные
   правила хранения, сроков и удаления (152-ФЗ).
4. **Контент и бренд друга** (`knowledge/uniqore-cases.md`, `pricing.md`, `sales-playbook.md`, партнёрские питчи,
   логотипы Orbit) принадлежит студии UniqOre. Брать как есть нельзя: нужны ваши кейсы, цены, голос.
5. **Права на код**: нужно письменное согласие друга на использование как основы и на продажу продукта третьим лицам.
6. **Однопользовательская архитектура**: один владелец, один ящик, один набор ключей, SQLite. Мульти-тенантность
   (наши 2–3 фрилансера) потребует переделки хранилища и ключей.
7. **Привязка к студии**: тексты, ниши, партнёрская схема «белый субподряд агентствам» нам не нужны.
8. **Ключи и доступы**: в архиве друга были копии `.env`. Им следует сменить ключи (Anthropic, Telegram, почта).

## 7. Влияние на архитектуру и стек
- Основная часть кода на **Python**. Курс (AI-Архитектор) даёт примеры на TypeScript. Либо остаёмся на Python и
  переиспользуем зрелый код, либо переписываем на TS. Я рекомендую **Python** (вопрос В2 в 06): выгода в сотни часов,
  курс учит паттернам, а не языку.
- Хранилище: SQLite → PostgreSQL (в РФ) при переходе на нескольких пользователей.
