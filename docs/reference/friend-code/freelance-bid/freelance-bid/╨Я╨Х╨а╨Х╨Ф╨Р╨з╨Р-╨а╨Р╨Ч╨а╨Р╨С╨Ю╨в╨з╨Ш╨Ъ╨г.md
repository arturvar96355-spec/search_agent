# Передача проекта разработчику

Софт собирает заказы с фриланс-бирж, сам пишет отклики и отправляет их. Работает
круглосуточно, управляется из Telegram. Ниже — всё, что нужно, чтобы поднять его
на сервере и не сломать.

## Первое, что нужно знать

**Здесь тратятся живые деньги.** Каждый отклик на Profi.ru списывается со счёта
(26–650 ₽ за штуку), а каждый разбор заказа — это запрос к Claude API. Поэтому
в коде много проверок, которые выглядят избыточными. Они не избыточные: каждая
стоит там из-за конкретного случая, и в комментарии рядом написано, из-за какого.

Перед правкой денежной части прочитайте `fbid/bidder.py` целиком — предохранители
собраны в одном месте намеренно.

## Что уже настроено и лежит в проекте

`.env` отдаётся **заполненным**, менять ничего не нужно:

| что | зачем |
|---|---|
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | тот же бот, что у владельца; команды принимаются только из его чата |
| `ANTHROPIC_API_KEY` | генерация текстов откликов |
| `PROXY_URL` | мобильный LTE-прокси, через него ходит браузер |
| `DRY_RUN=false` | боевой режим: отклики уходят по-настоящему |

Путей к базе и профилям в `.env` **намеренно нет**: они вычисляются от папки
проекта. Так папку можно перенести куда угодно, и ничего не сломается. Однажды
абсолютные пути там стояли, папку перенесли — софт молча создал пустые профили
браузера, то есть потерял сессии бирж. Не возвращайте их.

`profiles/` — сохранённые сессии бирж (куки Chromium). **Это живые доступы к
аккаунтам.** Копируются на сервер как есть, иначе придётся заходить заново через
SMS. В git не коммитятся.

`data/fbid.db` — база: заказы, отклики, траты, лимиты. Единственное, что нужно
бэкапить: без неё софт заново откликнется на уже отработанные заказы.

## Развернуть

```bash
git clone <репозиторий> /opt/freelance-bid && cd /opt/freelance-bid
python3.12 -m venv .venv
.venv/bin/pip install -e '.[browser,llm,dev]'
.venv/bin/playwright install chromium
# скопировать сюда .env, profiles/ и data/ с машины владельца
sudo apt install -y xvfb           # браузер запускается не headless
.venv/bin/python -m fbid.cli doctor # проверка: доступы, лимиты, база знаний
```

Дальше — `deploy/DEPLOY.md`: два systemd-юнита (основной цикл и телеграм-бот),
оба с `Restart=always`.

## Как это устроено

```
лента биржи → фильтры → рейтинг → модель пишет заход → предохранители → отправка
   pipeline     filters   scoring        llm              bidder        sources/
```

| модуль | за что отвечает |
|---|---|
| `pipeline.py` | проход сбора, очередь заказов, вечерний добор |
| `filters.py` + `filters.yaml` | дешёвый отсев: профиль, бюджет, возраст, стоп-слова |
| `scoring.py` | рейтинг 0–10: деньги, витрина услуг, свежесть, заказчик |
| `llm.py` + `knowledge/*.md` | текст отклика и вердикт «наше / не наше» |
| `bidder.py` | **все предохранители на деньги** |
| `limits.py` | лимиты, которые владелец меняет кнопками в боте |
| `policy.py` | где нельзя давать ссылки и контакты (Кворк, Юду) |
| `sources/` | адаптеры бирж: fl, profi, youdo |
| `tgbot.py` | пульт в Telegram |
| `store.py` | SQLite: заказы, отклики, траты, состояние |

## Что нельзя ломать

1. **`Decision.__bool__` равен `passed`.** Поэтому результаты проверок сравниваются
   с `None` явно: `if budget is not None`. Однажды `if budget:` молча пропускал
   каждый отказ, включая денежный.
2. **Окончательный статус отклика не затирается временным** (`store.record_bid`).
   Иначе заказ снова становится свободным и получает второй платный отклик.
3. **Один Chromium на профиль** (`browser.profile_lock`). Два процесса на одном
   каталоге профиля портят куки, а это живая сессия биржи.
4. **Один экземпляр `watch`** (`browser.single_instance`).
5. **Fail-closed везде, где деньги.** Не прочитался баланс, не прочиталась цена —
   не отправляем. Пропущенный заказ стоит ноль, лишний отклик стоит денег.
6. **`needs_browser` у адаптера площадки.** FL.ru читается обычным HTTP, Profi и
   Юду — только браузером, и подписи `fetch_details` у них разные. Общая точка —
   `pipeline.load_details`. Звать адаптер напрямую значит рано или поздно
   промахнуться аргументами прямо в момент отправки.

## Проверки перед коммитом

```bash
.venv/bin/python -m pytest -q      # 400 тестов
.venv/bin/ruff check fbid tests
```

Тесты изолированы от боевого `.env` (`tests/conftest.py`), и там же живёт тест,
который следит, чтобы тестовые настройки не разъезжались с боевыми: однажды
разъехались, и денежная часть проверялась по несуществующей конфигурации.

## Что не доделано

* **Отклик на Юду** — сбор работает, отправка нет: форма видна только под
  аккаунтом (`can_bid = False` в `sources/youdo.py`). Нужен `fbid login youdo`
  и калибровка формы.
* **Кворк** — аккаунт владельца заблокирован до сентября 2026. Политика «без
  ссылок и контактов» для него уже описана в `policy.py`, адаптера нет.
* **Двухфазный отклик на FL** — код есть, выключен: не откалиброваны селекторы
  чата по заказу (`FlSource.CHAT_FIELD`).
* **Автоответ клиенту** на первое сообщение: сейчас приходит только уведомление
  «клиент написал».

## Контакты и доступы

Все доступы — в `.env` и `profiles/`. Владельцу имеет смысл сменить ключ
Anthropic и токен бота после окончания работ: они лежат в файле открытым текстом,
иначе их не передать.
