# Браузерный поиск в 2ГИС — работа без API-ключа

Модуль, который ищет организации **прямо в вебе 2ГИС**, когда Places API недоступен
(демо-лимит исчерпан, ключ не куплен). Документ для разработчика: как устроено,
чем ограничено, что чинить при поломке.

**Код:** `parser/providers/browser.py`, класс `BrowserProvider.search()`.
**Переключатель:** `SEARCH_SOURCE` в `.env` (по умолчанию `auto`).

---

## 1. Зачем это вообще

Клиентский режим (поиск организаций с жалобами на связь в отзывах) изначально держался
на **2ГИС Places API**. У демо-ключа лимит **1000 запросов в месяц**. Когда он исчерпан,
API отвечает `403 Authorization error (key is blocked)` — и поиск возвращает ноль
по всем нишам и городам сразу.

Варианта было три: ждать обнуления лимита, купить платный доступ, или искать без API.
Сделан третий — он снимает зависимость от ключа навсегда.

> Партнёрский режим (`parser partners`) от всего этого **не зависит** — у него свои
> источники (каталоги + DuckDuckGo) и ключ 2ГИС ему не нужен никогда.

## 2. Как работает

### 2.1 URL и пагинация
```
https://2gis.ru/{слаг_города}/search/{запрос}          # страница 1
https://2gis.ru/{слаг_города}/search/{запрос}/page/2   # дальше
```
Слаги городов — в `browser.CITY_SLUGS` (15 городов). Города меню бота (`niches.CITIES`)
покрыты все — это проверяется тестом `test_city_slugs_cover_bot_cities`.

На странице **12 карточек**. Листаем максимум `_SEARCH_MAX_PAGES = 6` (≈72 организации
на пару «рубрика × город») либо до `max_results`, либо пока не кончатся новые.

### 2.2 Что делает провайдер по шагам
1. Берёт прокси из `ProxyPool` (`PROXY_URL`), запускает **один** Chromium
   (глобальный семафор `_BROWSER_SLOT` — два headless-Chromium не влезают в 2 ГБ RAM).
2. Открывает страницу выдачи. При таймауте — **до 3 попыток** (`_SEARCH_PAGE_ATTEMPTS`);
   мобильный прокси стабильно роняет примерно одну загрузку из четырёх.
3. `_pass_gate()` — проходит заглушку «обновите браузер», если она появилась.
4. Скроллит выдачу (ленивая подгрузка) и снимает карточки через `_SEARCH_CARDS_JS`.
5. Разбирает каждую карточку `_parse_search_card()` → рейтинг, число отзывов, адрес.
6. Дедуп по ID фирмы, отсев служебных ссылок `_is_junk_name()`.

### 2.3 Почему разбор такой, а не по CSS-классам
Классы у 2ГИС **обфусцированы** и меняются между сборками — привязываться к ним нельзя.
Поэтому:
- карточки ищем по `a[href*="/firm/"]` и поднимаемся к ближайшему контейнеру с текстом;
- поля достаём из **текста** карточки регулярками.

Что учтено в разборе (каждый случай встречался на живой выдаче):
- рейтинг слипается с числом оценок: `клиник4.8139 оценок` → 4.8 и 139
  (в регэкспе **нет** `\b` — между буквой и цифрой границы слова не существует);
- блоки карточки разделены **zero-width space** — это основной путь разбора адреса,
  он надёжнее регэкспа;
- в рекламных карточках разделителей нет, тип улицы с заглавной, а вместо пробела —
  неразрывный: `Улица Патриса Лумумбы,\xa061, Казань` — работает запасной путь;
- два порядка слов: `Марксистский переулок, 3` и `улица Ленина, 12`;
- номерные улицы: `1-й Колобовский переулок, 4`;
- служебные ссылки на `/firm/` («3 филиала», «Показать на карте», название города
  в хлебных крошках) отсеиваются, иначе в базу попадала «организация» с именем «Казань».

**Чего в карточке нет — остаётся `None`.** Ничего не достраиваем и не угадываем.

## 3. Что даёт и чего не даёт

| Поле | Браузерный поиск | Places API |
|---|---|---|
| Название | ✅ | ✅ |
| Ссылка на карточку (`source_url`) | ✅ | ✅ |
| Рейтинг | ✅ | ✅ |
| **Число отзывов** (сигнал платёжеспособности 💰) | ✅ | ✅ |
| Адрес | ✅ ~90% карточек | ✅ |
| Координаты, рубрика, часы работы | ❌ | ✅ |
| Телефон | ❌ | ❌ (`contact_groups` — платно отдельно) |

Телефоны в обоих режимах добираются **отдельным шагом** — браузерным добором карточки
(`enrich_with_browser`), он не изменился и от источника поиска не зависит.

**Замер на живом прогоне** (Казань, «стоматология», мобильный прокси):
30 организаций за 3 страницы ≈ **105 секунд**; 28 из 30 с адресом, 30 из 30 с числом
отзывов. То есть ~40–50 с на страницу выдачи против ~1 с у API.

## 4. Как включается

`.env`:
```
SEARCH_SOURCE=auto      # по умолчанию
```

| Значение | Поведение |
|---|---|
| `auto` | API 2ГИС, пока ключ жив; ключ не задан или отклонён → браузерный поиск |
| `2gis` | только API (при исчерпанном ключе поиск вернёт ноль) |
| `browser` | всегда браузер: ключ не нужен, лимитов нет, но медленно |

Переключение при `auto` — не только на старте: если ключ выгорает **посреди** прогона,
`pipeline._refresh()` пересобирает провайдеров и **перезапрашивает ту же пару** через
браузер. Без этого прогон из одного запроса вернул бы ноль.

Флаг блокировки (`dgis.KEY_BLOCKED`) взводится по ответу API, и дальше запросы к мёртвому
ключу не отправляются — иначе прогон «все ниши × все города» отстрелял бы сотни заведомо
провальных запросов. Но флаг **не вечный**: раз в 6 часов (`dgis._BLOCK_RECHECK_SECONDS`)
API получает один пробный шанс — когда демо-лимит обнулится (24.08) или будет куплен
платный ключ, бот сам вернётся на API **без рестарта**. Не ожил — флаг взводится снова.

Проверить, что сейчас активно:
```bash
parser doctor
```
Раздел «Источник клиентского поиска» покажет `SEARCH_SOURCE=... → сейчас работает: ...`.

## 5. Ограничения и риски (честно)

1. **Скорость.** ~40–50 с на страницу против ~1 с у API. Прогон «все ниши × все города»
   растягивается на часы. Оценка времени в боте это учитывает (`_eta_minutes`).
2. **Хрупкость.** Это скрейпинг SPA. Редизайн выдачи → разбор ломается. Регэкспы и JS
   собраны так, чтобы не зависеть от классов, но от структуры текста зависят.
3. **Прокси обязателен.** Датацентр-IP 2ГИС банит. Мобильный прокси нестабилен — отсюда
   ретраи. Без `PROXY_URL` на VPS работать не будет.
4. **Память.** Chromium ест 400–600 МБ. На 2 ГБ сервере это узкое место, поэтому
   `_BROWSER_SLOT` жёстко разрешает только один браузер на процесс.
5. **Нет координат/рубрик/часов** — они есть только в API.
6. **robots.txt.** Проверено на 30.07.2026: в `https://2gis.ru/robots.txt` для `User-agent: *`
   закрыты `/_/*`, `/maps_action`, личный кабинет (`*/my*`, `*/user*`) и служебные
   параметры. Пути `/{город}/search/…`, `/page/N` и `/firm/…` **не запрещены**, отдельного
   `Crawl-delay` для `*` нет. Тем не менее это скрейпинг: **ToS 2ГИС строже robots.txt**,
   массовый парсинг выдачи он не приветствует. Пользоваться умеренно, с паузами
   (`REQUEST_DELAY`), а при появлении денег переходить на платный Places API.

## 6. Что чинить, если сломалось

**Симптом: «собрано 0 организаций», карточек нет.**
1. `parser proxy-check` — жив ли прокси, не забанен ли IP.
2. Открыть URL выдачи руками в браузере: не появилась ли капча/гейт.
3. Если страница открывается, но карточек 0 — сменилась разметка. Смотреть
   `_SEARCH_CARDS_JS`: селектор `a[href*="/firm/"]` и подъём к контейнеру.

**Симптом: организации есть, но адрес/рейтинг `None`.**
Снять сырые карточки и посмотреть глазами на текст:
```python
cards = await page.evaluate(_SEARCH_CARDS_JS)   # см. блок отладки ниже
```
Дальше править `_parse_search_card`, `_SEARCH_RATING_RE`, `_ADDRESS_*_RE`.
Каждый исправленный случай — **сразу тестом** в `tests/test_core.py` (разбор карточки)
или `tests/test_edge.py` (мусор и краевые случаи). Сейчас в проекте 138 тестов, все зелёные.

**Симптом: в базе организация с именем города или «3 филиала».**
Появился новый вид служебной ссылки — дополнить `_JUNK_NAME_RE`.

**Отладочный сниппет** (снять сырые карточки в JSON):
```python
import asyncio, json
from parser.config import get_settings
from parser.providers.browser import (_CHROMIUM_ARGS, _USER_AGENT, _SEARCH_CARDS_JS,
                                      _proxy_config, ProxyPool, _pass_gate)

async def main():
    s = get_settings()
    from playwright.async_api import async_playwright
    async with async_playwright() as pw:
        b = await pw.chromium.launch(headless=True, args=_CHROMIUM_ARGS,
                                     proxy=_proxy_config(ProxyPool(s.proxy_list()).current))
        page = await (await b.new_context(user_agent=_USER_AGENT, locale="ru-RU")).new_page()
        await page.goto("https://2gis.ru/kazan/search/автосервис",
                        wait_until="domcontentloaded", timeout=90000)
        await _pass_gate(page); await asyncio.sleep(4)
        await page.mouse.wheel(0, 2500); await asyncio.sleep(2)
        json.dump(await page.evaluate(_SEARCH_CARDS_JS), open("cards.json", "w"),
                  ensure_ascii=False, indent=1)
        await b.close()

asyncio.run(main())
```

## 7. Когда переходить обратно на API

Браузерный поиск — это способ не стоять без лидов, а не замена API. Как только
появляется бюджет:

1. Купить Places API в Platform Manager (platform.2gis.ru).
2. Прописать ключ в `DGIS_API_KEY`, поднять `PAGE_SIZE` (на платном тарифе предел выше 10).
3. Ничего больше менять не нужно: `SEARCH_SOURCE=auto` сам вернётся на API —
   он всегда предпочитает API, пока ключ жив.

Держать `SEARCH_SOURCE=auto` можно постоянно: это и страховка на случай, если платный
лимит однажды кончится посреди рабочего дня.
